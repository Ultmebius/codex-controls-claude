# Worker and call-layer policy

This inventory reflects the user's final instruction: start native Claude Code, assign work, inject communication MCP, and leave ordinary execution to Claude. The plugin installs no native tool blocks, so subagents and team tools follow the user's own Claude Code settings; the plugin's three-execution ceiling governs only the top-level workers it schedules.

## Native behavior

Claude Code manages its native terminal title. The plugin initializes a neutral caption after its private startup handshake and passes native title updates through without injecting a title-disable flag. Worker names remain task and audit labels. HWND/PID/full private ownership identity authorize window cleanup; captions are diagnostic so a native/user rename cannot strand an owned window.

| Area | Current behavior |
| --- | --- |
| Hooks | No plugin hook callbacks and no settings override. User/project/local hooks, including disable/enable choices, are untouched. |
| Ordinary tools | Claude Code built-in preset plus its own enabled MCP configuration. No copied Codex MCP configuration or ordinary tool allowlist. |
| Display | OUTPUT is rendered as lightweight terminal Markdown (headings, lists, quotes, bold, inline code, fenced code, pipe tables with aligned/wrapped columns and a literal fallback when columns cannot fit); TASK/TOOL/SYSTEM/RESULT/ERROR stay literal. The full task title is stored and fitted to the drawn heading row, so a wide terminal shows it whole. A browsing viewport is anchored to the text being read, so new output does not move it until the user returns to the bottom. |
| Subagents | No plugin block. Agent/TeamCreate/TeamDelete/Task follow native permissions and `disallowedTools`; the prompt tells the worker that subagents are available. The plugin's three-execution ceiling counts only the top-level workers it starts and is not an OS sandbox against arbitrary shell or nested processes. |
| Permission mode | Reads configured permissions.defaultMode by scope and passes it to the pinned SDK. Actual init metadata is authoritative. Auto uses native classification; bypass avoids ordinary approval requests. Native explicit ask/deny rules still apply. A temporary mode switch in another interactive window is not a configuration change for this session. |
| Tool input | Passed through unchanged. Native-mode calls skip the inherited bridge's Windows path normalization, POSIX path veto and secondary allowlist checks. Native residual approval responses preserve the original input. |
| File access | No plugin file interception or PreToolUse scope gate. writeScope is a scheduling/audit reservation. Native permissions govern access. Out-of-reservation changes are observations to review, not silently assumed to belong to a peer. |
| Worker validation | Allowed normally. Codex still independently verifies actual artifacts and original fixed checks. A specific task can request a read-only investigation or omit tests when that is the assigned work. |
| Model | User-requested ANTHROPIC_MODEL precedence and existing authentication/gateway environment. No forced model family or fallbackModel option. Warm queries keep their startup model until close/resume/new. |
| Settings | user, project and local sources load natively; no rewritten .claude.json/settings files. No injected settings object. `settingSources` is stated explicitly and non-empty, because the `claude_code` system-prompt preset does NOT imply filesystem settings and `project` is required for CLAUDE.md. No suppression path is injected (`CLAUDE_CODE_DISABLE_CLAUDE_MDS`, `CLAUDE_CODE_SIMPLE`/`--bare` are never set), and the worker keeps the user/project/local CLAUDE.md memory files it would have in an ordinary native session. Regression tests assert the option, the preset with its append and the absence of those switches. |
| Terminal startup | The worker's window is created minimized (no focus steal), then restored without activation and buried so its dashboard paints behind the foreground window while the worker starts. The host waits for the first painted conversation frame and then minimizes exactly once, so the taskbar preview is composed from the real dashboard rather than the empty startup frame. Nothing is activated, a user-restored window is never touched, there is no re-minimize loop, and readiness never gates the SDK handshake. |
| Communication | One query-local codex_supervisor MCP with milestone receipt and scoped question/reply tools. Native existing servers keep their settings/switches. |
| User questions | Native `AskUserQuestion` is answered from Codex, not from the terminal: the SDK `canUseTool` callback forwards a `worker_question` event carrying the original `questions` (all text, headers, options, multiSelect flags) and waits for `orchestrator_message`. The reply must be `{"answers":{"<exact question text>":"<label or free text>"}}`; a single question also accepts plain free text, and a multiSelect answer may be a JSON array of labels, joined with `", "` as Claude does natively. The MCP returns the native `updatedInput` with the original questions plus `answers`. Timeout, cancellation, attempt reset, a stale ID, an incomplete reply or an unparseable reply yields an explicit deny with the unanswered question text so the worker reports BLOCKED; no answer is ever inferred. This path creates no ordinary permission record and does not change the permission mode. |
| Retry | Streaming worker input does not use the upstream bridge's transient-query replay branch. Native Claude/provider retries remain native. Recovery never silently reruns a task. |

## Controls retained in orchestration

These govern dispatch, evidence and owned process lifetime, not individual native tool permission.

| Control | Default / behavior |
| --- | --- |
| Managed concurrency | Exactly3 active executions shared across every connected chat, ordinary run, team child, continuation and model-executing maintenance; retained idle transcripts consume none. A fourth waits for an owned slot to finish. Dependencies and conflicting declared reservations also gate dispatch. |
| Segment/run turns | 500 native agentic rounds per segment;1000 persistent SDK-reported turns per run/team. Explicit create overrides and same-task continuation remain supported; provisional charges are disclosed separately. |
| Model execution time | Segment/run2h; no silent reset on resume/rework/append. Acceptance/reconciliation may finish after model budget expires. |
| Explicit expired-run renewal | Only an evidence-backed `plan sessionAction=resume` (or team `resume`) on an expired open run moves the run/team deadline, default2h or `runTimeoutMs`1s..2h, forward only. It requires every worker idle and a live owner; the native conversation, contracts, revisions, checks, receipts and turn budget are unchanged. Reopen/append/compact/new and a dispatch after a failed worker never renew. |
| Acceptance | Immutable dispatched contract/checks, fresh artifact/revision hash, independent Codex evidence, fixed-check rerun and dependency acceptance. Additional artifacts inside the task workspace need explicit acknowledgement. This evidence boundary does not prevent Claude from accessing files elsewhere. |
| Rework | Two acceptance repairs by default; budget continuation is separately counted. |
| Context maintenance | Soft suggestion near300K and maintenance before400K, reduced for smaller reported windows. Unknown context remains unknown. |
| Native startup handshake | Default120s; CCC_INIT_TIMEOUT_MS configures1s..10min. |
| Fixed acceptance checks | Default5min overall per review; CCC_CHECK_TIMEOUT_MS configures1s..10min. |
| Residual native decisions / supervisor questions | Default5min; CCC_DECISION_TIMEOUT_MS configures1s..30min. Expired content remains available and requires fresh evaluation on explicit continuation. |
| Event wait transport | One pending event promise, default and maximum1200000ms (20min), overridable downward with CCC_WAIT_MS. Completion, questions, residual permissions, failures, budget risk and cancellation resolve it immediately. Omit `timeoutMs` so the 20-minute default applies; never shorten it for progress updates, a speculative host limit, a `functions.exec` yield setting or an outer `functions.wait` bound, because those do not terminate the server-side wait. Only an actually observed host tool-timeout failure that cut a call short justifies a shorter value, with the exact error text and bound recorded. `functions.wait` resumes the same running exec and never reissues the event wait. No worker status/log polling; ordinary milestones are audited without waking Codex. |
| Communication resource bounds |16K characters/message,128 message IDs/attempt,16 pending questions. Explicit errors on limits; no silent loss of decision evidence. |
| Active guidance (queue/interrupt) | `orchestrator_message action="queue"` accepts scoped guidance for an active running task and delivers exactly one input at the next native result boundary of the same conversation, FIFO; `action="interrupt"` also asks the native runtime to end the current turn and delivers ahead of unsent queued messages once that segment drains. The follow-on segment is reserved from the persistent turn budget before any input is written, so guidance can never bypass the allowance, and a changed native cap cold-resumes the same saved session. States are transport truth only — `queued`, `interruption_requested`, `delivering`, `delivered`, `failed`, `cancelled` — and `delivered` never claims the model read the text. Bounded at8 unsent,32 accepted records per run and4000 characters; unsent guidance is cancelled, never replayed, on restart, cancellation, stop, session change or a new dispatch. |
| Idle review lifecycle | Useful session retained for user review, suspended after30min idle with transcript preserved. Explicit close/cancel affects owned processes only. |
| Connection ownership | Unique owner/generation, atomic explicit attach, no live-owner takeover. Idle execution leases are released. |
| Terminal display | Each worker has its own C# dashboard and terminal, with local elapsed clock, observed model/effort/native permission mode and activity; provenance stays in backend evidence. Conversation selectors appear only for multiple actual native session IDs inside that terminal; separate terminals never share a dashboard. Effort observation does not override native settings. CCC_TERMINAL_COLOR=never selects plain output. |
| GUI test ownership | Codex launches, captures and closes only specifically verified test windows using nonce/title, HWND and PID. Workers edit, compile and run noninteractive checks. Windows Terminal can share a broker process across unrelated windows: no termination by process name or broker PID. This is explicit task-scope guidance, not a new native tool veto, hook or permission mode. |

No plugin-native tool blocks remain. The three-execution ceiling, write-scope reservations and acceptance gate are orchestration controls; no plugin claim of filesystem isolation or measured billed-token savings follows from them.
