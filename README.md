# Codex Controls Claude

A local Codex plugin combining a stdio MCP, orchestration skills and diagnostic scripts. Codex owns planning and independent acceptance; Claude Code executes scoped tasks using your configured model.

Explicitly invoke this plugin or its `orchestrate` skill to activate Claude Code assistance. Generic coding requests do not activate it. Authorized follow-ups may continue the same run. The MCP records task dependencies and contracts, waits for actionable SDK events, reruns independent acceptance checks, records rework and unlocks accepted dependencies.

Prerequisites: Node 22+, local Claude Code, Windows Git Bash where applicable, and existing authorized Claude Code authentication or gateway settings. Model selection reads `~/.claude/settings.json` `env.ANTHROPIC_MODEL` first, then existing environment or top-level `model`, otherwise the native Claude Code default. Warm sessions keep their startup model; close/resume or start a new session to apply a model change. Run the setup skill or `node scripts/doctor.mjs` to diagnose prerequisites. Local gateway credentials are loaded at runtime and are not included in this package.

Codex can explicitly schedule one to three Claude Code workers. Use the ordinary plan for one worker or `orchestrator_team` for independent parallel tasks. Teams reserve literal write scopes or separate workspaces, enforce dependencies and share a persistent turn allowance. Defaults: 40 native agentic rounds per segment, 200 SDK-reported turns per run/team, two hours per execution segment/run, and two acceptance repairs. Budget continuation, interruption recovery and acceptance rework have separate counters. Explicit supervisor interrupt captures a recoverable checkpoint; follow-ups never reset the allowance or deadline. The supervisor reviews requested command tools and interprets evidence. File scope checks are not an operating-system shell sandbox.

On Windows the actual Claude Code execution process is hosted in a dedicated Windows Terminal window, launched minimized. Restore its taskbar window to see Codex tasks, tool activity and model replies. This is the supervised SDK session display; permission decisions remain in Codex. Closing the window stops that execution. The plugin closes only its own host/process tree and dedicated window. Windows Terminal (`wt.exe`) and .NET 10 runtime are required. A compiled C# helper owns native window control, pipe transport and the visible Claude process; no PowerShell or runtime compilation is used.

Warm tasks reuse a live SDK session. After technical acceptance the candidate waits for user review; the supervisor retains it for useful follow-up or closes it with its transcript preserved. Human approval completes the run and closes the worker. Idle review sessions suspend after 30 minutes. Saved sessions resume on the next explicit task.

Normal output is compact with an explicit truncation marker and per-task evidence retrieval. Critical blockers/errors remain complete. Context alarms use the latest response's reported context usage from the SDK stream, or one local SDK transcript read at completion when stream usage is absent. Unknown usage is null and explicitly marked. No transcript polling is used. Thresholds: consider compact/new around 300K, maintain before 400K, with smaller limits for smaller reported windows. New contexts carry a deterministic supervisor checkpoint.

`orchestrator_wait` uses event-triggered promises with a 45-second transport deadline. Empty waits are renewed without querying worker state. Supervision occurs during active Codex work; this package does not promise to wake a closed chat.

The package includes a built server and its maintained source subset under `server/source`. Development checkout, dependencies, test fixtures and reports are maintained in the surrounding workspace. See `UPSTREAM.md` and `THIRD_PARTY_NOTICES.md` for provenance and licenses.

Native tools and the user's enabled Claude MCP configuration are inherited. Worker subagent/team spawning tools are disabled so Codex controls the three-worker ceiling. Dispatch instructions describe the task rather than assuming supervisor tool names. Sanitized actual capabilities distinguish pending/connected servers; relevant native config changes reload the saved conversation at task boundaries. No Codex MCP configuration or credentials are copied.

Each query receives a fresh in-process `codex_supervisor` MCP server. Claude calls `notify_supervisor` for milestones or `ask_supervisor` for questions; the callback wakes the existing Codex event wait immediately. Codex answers through `orchestrator_message`, and the answer returns inside Claude's original tool call. The default question deadline is60 seconds; stale answers, cancellation and timeout are explicit. A delivery receipt is not execution completion, acceptance or additional user authorization. No extra daemon or global Claude MCP configuration is required.

Team events carry childRunId, which routes existing review/status/permission/message tools. Dispatch team children only through the coordinator so budgets, scopes and capacity remain enforced. Review checks wait for overlapping workspaces to become quiescent; checks are serialized by the server. Use separate Git worktrees for overlapping changes and explicitly integrate accepted results; worktree creation does not copy uncommitted main-workspace edits. Teams currently use fixed DAGs; append/update/supersede and compaction remain single-run features. For team context maintenance, use child `sessionAction=new` to carry a checkpoint, then explicitly dispatch through the same team budget.

`dispatch(mode="continue")` resumes a budget-stopped task with its original contract. `plan(action="reconcile")` captures supervisor-completed current artifacts without model replay; normal review executes the original checks once. `status(sections=["result","checks","artifacts"])` returns targeted evidence without repeated contract/usage. Full evidence remains available. Verification may finish after the model-execution deadline.
